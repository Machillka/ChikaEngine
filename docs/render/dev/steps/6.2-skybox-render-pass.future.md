# Step 6.2 - Skybox Render Pass

## Metadata

- Status: Planned
- Depends on: Step 6.1
- Estimate: 2-3 days

## Goal

增加可配置 Skybox 渲染路径，让场景背景来自环境 Cubemap，并为 IBL、反射探针和视觉回归提供一致的环境输入。

Skybox 是环境显示功能，不等同于全局光照；它只负责把环境贴图正确画到 HDR Scene Color 中。

## Responsibility

- RenderSettings 暴露 Skybox 开关、曝光/强度和 fallback 颜色。
- RenderPipeline 在 Opaque/GBuffer Lighting 前后选择稳定插入点，避免污染 depth 和 transparent pass。
- RenderGraph 使用 Blackboard 连接 `HDRSceneColor`、`SceneDepth` 和 `Environment.Skybox`。
- Deferred 路径必须读取 depth，只填充未被几何覆盖的背景像素。
- Shader 通过 Reflection 绑定 cubemap 和 frame data，不新增手写 binding 数字。

## Implementation

- 新增 `PassModules::AddSkybox()`，写入 `HDRSceneColor`，读取环境 cubemap，不写 depth。
- Skybox vertex path 使用 fullscreen triangle 或 cube mesh；如果使用 cube mesh，view matrix 需要移除 translation。
- 深度策略保持稳定：Skybox 不影响 scene depth，不能遮挡 opaque、transparent 或 debug overlay。
- Forward 模式中先绘制 Skybox 再绘制 Opaque，Opaque 用 `LoadOp::Load` 或明确的 pass 顺序保留背景。
- Deferred 模式中首版选择独立 pass：在 Deferred Lighting 后读取 `SceneDepth`，只在 clear depth / far depth 区域写 Skybox，避免覆盖 GBuffer 几何光照结果。
- 缺少环境 Cubemap 时使用 `RenderSettings` fallback color，不让 shader 采样无效 descriptor。

## Unit Tests

- Pass 顺序覆盖 Forward 和 Deferred：Skybox 必须发生在 Post Process 前。
- Skybox pass 不声明 depth write。
- Shader Reflection 能解析 cubemap binding 和 frame settings binding。
- 关闭 Skybox 时不创建 Skybox pass，Frame Pass Count 可预测。
- Resize 后 Skybox 仍写入新的 HDR Scene Color。

## Delivery Checklist

- [ ] Forward 和 Deferred 都能看到环境背景。
- [ ] 移动相机时 Skybox 不发生平移，只响应旋转。
- [ ] Skybox 不覆盖透明物体、调试线框和 UI overlay。
- [ ] `RenderGraphDebugSnapshot` 显示清晰的 Skybox pass 和资源依赖。

## Boundaries

- 不在本步骤实现 IBL 光照。
- 不实现动态天空、大气散射、太阳盘或云。
- 不把 Skybox 作为普通 `RenderObjectProxy` 插入 RenderQueue。
- 不为 Skybox 引入 Gameplay 组件依赖。
