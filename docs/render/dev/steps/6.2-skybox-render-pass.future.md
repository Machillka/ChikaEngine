# Step 6.2 - Skybox Render Pass

## Metadata

- Status: In Progress (resource resolution/import implemented 2026-07-15; render pass pending)
- Depends on: Step 6.1
- Estimate: 3-4 days

## Goal

增加可配置 Skybox 渲染路径，让场景背景来自环境 Cubemap，并为 IBL、反射探针和视觉回归提供一致的环境输入。

Skybox 是环境显示功能，不等同于全局光照；它只负责把环境贴图正确画到 HDR Scene Color 中。

## Progress - 2026-07-15

已完成第一段“环境资源解析与 RenderGraph 导入”：

- `EnvironmentSettings` 已具备稳定 `AssetReference`、intensity、fallback 策略和 fallback color。
- `EnvironmentResourceResolver` 已实现 Asset/Resource 缓存、Cubemap 契约校验和 stale handle 恢复。
- `RenderPipeline` 会在 drain upload jobs 前解析环境资源，并发布 Blackboard `Environment.Skybox`。
- 同帧首次上传会复用 upload destination RG handle；缓存 ready 资源才单独 import。
- 默认 `default-skybox.texture`、稳定 `.meta` 和资源集成测试已经落地。

仍未实现 `PassModules::AddSkybox()`、shader、`SkyboxData`、Forward/Deferred pass 顺序和实际画面验证。

## Responsibility

- `RenderSettings::environment` 只保存 Skybox 开关、稳定的 `Asset::AssetReference`、强度和 fallback 策略，不保存原始 RHI handle。
- `RenderPipeline` 通过 `AssetManager -> ResourceManager` 解析并缓存 Cubemap GPU 资源，再把它导入 RenderGraph 并发布为 `Environment.Skybox`。
- RenderGraph 使用 Blackboard 连接 `HDRSceneColor`、`SceneDepth` 和 `Environment.Skybox`，Pass 不绕过语义表直接持有临时图资源。
- Forward 与 Deferred 使用明确且不同的插入点，并同时覆盖 CPU 与 GPU-driven 路径。
- Shader 通过 Reflection 绑定 Cubemap、Skybox frame data 和可选的 `SceneDepth`，不新增手写 binding 数字。

## Decisions

- 首版使用 fullscreen triangle，不引入 Skybox mesh、`RenderObjectProxy` 或额外顶点缓冲。
- 新增独立 `SkyboxData` UBO，至少包含移除相机平移后的 inverse view-projection 和 intensity；不把 Skybox 专用数据继续塞入共享 `SceneData`。
- Skybox 只使用 `environment.intensity`；显示曝光仍由 Post Process 的全局 exposure 负责，避免重复曝光。
- 当前深度约定是 `LessOrEqual + clear depth 1.0`。Deferred shader 必须以统一常量/参数判断背景像素，不在多个位置复制不同的 magic value。

## Resource and Ownership Flow

```text
RenderSettings.environment.skybox (AssetReference)
  -> AssetManager::LoadTexture()
  -> ResourceManager::UploadTexture() cache
  -> TextureGPU default cube view + sampler
  -> reuse pending upload RG handle / import ready texture
  -> Blackboard Environment.Skybox
  -> Skybox Pass reflection binding
```

- `EnvironmentSettings` 增加 `skybox` 和 `fallbackColor`；`skybox` 的 expected type 必须是 Texture。
- `RenderPipeline` 只缓存 `Resource::TextureHandle`，GPU 纹理所有权仍归 `ResourceManager`；配置变化、资源 reload 或失效时重新解析，不自行销毁 ResourceManager 资源。
- 仅当资源是 `TextureDimension::TextureCube` 且 cube view、sampler 均有效时，才发布 `Environment.Skybox`。
- 新资源若在当前帧仍有 pending upload，`Environment.Skybox` 必须复用 `Upload Resources` 已注册的 destination RG handle；禁止把同一物理纹理重复导入为两个无依赖的逻辑资源。
- 在现有六张 Skybox face 基础上提交一个 `.texture` descriptor，作为默认 smoke/回归资源，避免验收依赖工作区外资源。

## Implementation

### 1. Resolve and import the environment

- [x] 在收集本帧 upload jobs 前解析 `environment.skybox`，复用 `AssetManager` 与 `ResourceManager` 已有缓存，不在逐帧路径重复上传 Cubemap。
- [x] `AddUploadPasses()` 为本帧 texture upload 暴露 `RHI TextureHandle -> RGTextureHandle` 映射。Skybox 纹理命中该映射时复用 destination handle，使 RenderGraph 建立 `Upload Resources -> Skybox` 的写后读依赖。
- [x] 缓存资源没有 pending upload 时，才按 `TextureGPU` 的真实 descriptor 单独导入；初始/最终状态使用 `ShaderResource`。两种路径最终都设置 Blackboard `Environment.Skybox`。
- [x] Skybox 关闭时不解析资源、不导入 Cubemap，也不创建 Skybox pass。

### 2. Add the pass

- 新增 `PassModules::AddSkybox()`：读取 `Environment.Skybox`，由调用方显式传入 HDR `LoadOp` 和是否采样 `SceneDepth`，不声明 depth write。
- fullscreen vertex shader 根据 `gl_VertexIndex` 生成三角形；`SkyboxData` 提供只包含相机旋转的重建矩阵，保证相机平移不改变天空盒。
- Fragment shader 对 Cubemap 采样结果应用 intensity，并保持 HDR 线性颜色输出；tone mapping 与 exposure 仍由 Post Process 完成。

### 3. Forward ordering

- CPU Forward：`Skybox -> Main Scene`。Skybox 作为 HDR 首个写入者，以 `fallbackColor + LoadOp::Clear` 开始；`PassModules::AddForward()` 的 HDR attachment 改为 `LoadOp::Load`，SceneDepth 仍由 Main Scene clear。
- GPU-driven Forward：`Skybox -> GPU Driven Forward`。Skybox 同样 clear HDR，GPU pass 的 HDR attachment 改为 `LoadOp::Load`，SceneDepth 仍由该 pass clear。
- 如果 Skybox 关闭或没有可绑定的 Cubemap，两条 Forward path 都保留首个 scene pass 的 `fallbackColor + LoadOp::Clear`；禁止在未初始化 HDR attachment 上直接 `Load`。

### 4. Deferred ordering and depth sampling

- CPU/GPU Deferred 统一使用 `GBuffer -> Deferred Lighting -> Skybox -> Transparent`；Skybox 必须发生在 Post Process 前。
- Deferred Lighting 先以 `fallbackColor + LoadOp::Clear` 写 HDR；Deferred Skybox 再以 `LoadOp::Load` 读取 `SceneDepth`，只在 clear/far depth 区域写入背景，保留几何像素。
- `m_depthTexture` 的创建、resize 重建和 RenderGraph import descriptor 都增加 `RHI_TextureUsage::Sampled`，保持物理纹理与图描述一致。
- RenderGraph 必须产生 `DepthWrite -> ShaderResource` 转换；Skybox pass 不把 `SceneDepth` 同时声明为 depth attachment，避免 sampled depth 与 writable depth 的同 pass 冲突。

### 5. Fallback behavior

- `enabled == false`：不创建 Skybox pass，管线的首个 HDR 写入者使用 `fallbackColor` clear。
- Cubemap 有效：创建 Skybox pass 并绑定真实 cube view。
- Cubemap 缺失/类型错误且 `useFallback == true`：绑定 Step 6.1 的有效 fallback cube；若 fallback cube 也不可用，则只保留 `fallbackColor`，绝不绑定无效 descriptor。
- Cubemap 缺失/类型错误且 `useFallback == false`：记录一次可定位诊断并跳过 Skybox pass，仍以 `fallbackColor` 保证确定性画面。

## Unit Tests

- Pass 顺序覆盖 CPU/GPU-driven 的 Forward 和 Deferred：Skybox 必须发生在正确的 scene pass 之间且早于 Post Process。
- Forward 开启 Skybox 时，Skybox clear HDR 且两条 Forward scene path 都以 `LoadOp::Load` 保留背景；关闭或资源失效时首个 scene pass 仍显式 clear。
- Deferred Lighting clear HDR，Deferred Skybox 声明 `SceneDepth` sampled read 和 `HDRSceneColor` load/write，不声明 depth write。
- SceneDepth 的首次创建、resize 和 RenderGraph import descriptor 均包含 `DepthStencilAttachment | Sampled`。
- Shader Reflection 能解析 Cubemap、`SkyboxData` 和 Deferred depth binding。
- 关闭 Skybox 或资源失效时不创建非法 pass、不绑定无效 descriptor，Frame Pass Count 可预测。
- `AssetReference -> TextureCube -> Resource::TextureHandle -> Environment.Skybox` 导入链能够命中缓存并拒绝 2D texture。
- Cubemap 首次加载时复用 upload destination RG handle，DebugSnapshot 中存在 `Upload Resources -> Skybox` 依赖且没有重复 physical import。
- Resize 后 Skybox 写入新的 HDR Scene Color，并读取新的 SceneDepth。

## Boundaries

- 不在本步骤实现 IBL 光照。
- 不实现动态天空、大气散射、太阳盘、云或 Skybox rotation 控件。
- 不把 Skybox 作为普通 `RenderObjectProxy` 插入 RenderQueue。
- 不为 Skybox 引入 Gameplay 组件依赖。
- 不在本步骤实现 HDR 源纹理格式升级或 Cubemap mip 生成；沿用 Step 6.1 已记录的限制。
