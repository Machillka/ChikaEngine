# Step 7.1 - Material Parameter Editing API

## Metadata

- Status: Implemented (2026-07-02)
- Depends on: Renderer Step 1.7 material reflection layout, Renderer Step 2.3 render bridge, Renderer Step 5.2 PBR foundation
- Related editor card: `docs/editor/dev/material-inspector-editing.future.md`
- Estimate: 2-3 days

## Goal

为 Renderer/Resource 层增加 Material 字段修改接口，使调用方可以按反射参数名修改材质数值，例如 `BaseColor`、`Emissive`、`Metallic`、`Roughness`、`OcclusionStrength` 和 `NormalScale`。

第一阶段只解决运行时材质参数编辑和 GPU UBO 更新，不做材质 JSON 持久化，也不引入复杂 Material Instance 系统。

## Current Context

- `MaterialLoader` 已把 material JSON 的 `parameters` 拍平成 `floatParams` 和 `vectorParams`。
- `ResourceManager::_UploadMaterial()` 已通过 Shader Reflection 的 `material` uniform buffer 获取真实 offset/size，并在上传时一次性写入 `uboBuffer`。
- 实现前，`MaterialGPU` 只保存 pipeline、shader、`uboBuffer`、binding group 和透明/遮罩标记，不保存可再次编辑的参数元数据。
- 实现前，`Renderer` 只暴露渲染设置接口，例如曝光、Bloom、FXAA、Ambient，不暴露 Material 参数编辑 API。

## Responsibility

- Asset 层继续负责读取 material JSON 和 shader template 默认值。
- Resource 层拥有 `MaterialGPU`、UBO、Reflection offset 和实际 GPU 参数写入。
- Renderer Facade 提供编辑器可调用的稳定接口，不让 Editor 直接理解 Shader Reflection 或 UBO offset。
- RenderPipeline 不参与 Material 参数编辑；它只消费已经绑定好的 Material resource。

## Proposed Public Contract

新增后端无关的参数描述与值类型：

```cpp
enum class MaterialParameterType
{
    Float,
    Vec2,
    Vec3,
    Vec4,
    Bool,
};

struct MaterialParameterInfo
{
    std::string name;
    MaterialParameterType type;
    uint32_t componentCount;
    std::vector<float> value;
    std::vector<float> defaultValue;
};
```

Renderer Facade 推荐暴露这些最小接口：

```cpp
std::vector<MaterialParameterInfo> GetMaterialParameters(Resource::MaterialHandle material) const;
bool SetMaterialFloat(Resource::MaterialHandle material, std::string_view name, float value);
bool SetMaterialVector(Resource::MaterialHandle material, std::string_view name, std::span<const float> value);
bool SetMaterialParameter(Resource::MaterialHandle material, std::string_view name, const MaterialParameterValue& value);
```

ResourceManager 内部提供对应实现：

```cpp
const MaterialParameterRuntime* FindMaterialParameter(Resource::MaterialHandle material, std::string_view name) const;
bool UpdateMaterialParameter(Resource::MaterialHandle material, std::string_view name, std::span<const float> value);
```

## Implementation Steps

1. [x] 在 `ResourceLayout.hpp` 中为 `MaterialGPU` 增加 CPU shadow data：
   - `std::vector<uint8_t> parameterData`
   - `std::unordered_map<std::string, MaterialParameterRuntime> parameters`
   - `uint64_t parameterBufferSize`

2. [x] 在 `ResourceManager::_UploadMaterial()` 中构建参数 runtime 表：
   - 从 shader template 的 `parameters` 遍历公开参数。
   - 用 `ShaderProgramInterface::FindBufferMember("material", name)` 获取真实 offset/size/type。
   - 记录参数类型、component 数、offset、size、默认值和当前值。
   - 使用 Reflection 驱动的参数写入逻辑初始化 `parameterData`。

3. [x] 在 ResourceManager 中增加参数更新接口：
   - 校验 material handle 有效。
   - 校验参数名存在。
   - 校验传入 component 数与反射类型一致。
   - 把新值写入 `MaterialGPU::parameterData`。
   - 把同一段 bytes 写入 `m_rhi.GetMappedData(material.uboBuffer)` 返回的 mapped memory。

4. [x] Renderer Facade 增加薄包装：
   - `Renderer` 调用 `m_resourceSystem.GetResourceManager()`。
   - 不把 RHI、UBO pointer 或 Reflection type 暴露给 Editor。
   - 失败时返回 `false`，日志由 ResourceManager 输出具体原因。

5. [x] 保持 Draw 路径不变：
   - `MaterialGPU::bindings` 继续绑定同一个 `uboBuffer`。
   - 数值参数修改不重建 pipeline。
   - 数值参数修改不重建 descriptor set。

6. [x] 明确共享语义：
   - MVP 修改的是共享 Material resource。
   - 多个对象使用同一个 material asset 时，都会看到同一次参数修改。
   - Editor per-object preview 通过 `ResourceManager::CloneMaterial()` 创建 runtime material instance，不改变共享 API 的默认语义。

## Implementation Record

- `MaterialGPU` 现在保存反射参数表、当前 CPU shadow bytes 和 UBO byte size。
- 参数初始化继续从 shader template 默认值和 material JSON override 解析，但写入位置只来自 Shader Reflection 的 `material` uniform buffer。
- `ResourceManager::GetMaterialParameters()` 返回按名称排序的参数列表，供 Inspector 稳定展示。
- `ResourceManager::UpdateMaterialParameter()` 会先写入 shadow copy，再写入 mapped UBO；错误 handle、错误参数名、错误 component 数和类型不匹配都会返回 `false`。
- `ResourceManager::CloneMaterial()` 复用 shader/pipeline/texture 绑定，为 runtime material instance 创建独立参数 UBO，避免 Inspector 修改选中对象时污染共享材质。
- `Renderer` 暴露 `GetMaterialParameters`、`CreateMaterialInstance`、`SetMaterialFloat`、`SetMaterialVector`、`SetMaterialParameter`，不暴露 UBO offset 或 RHI pointer。
- 7.1 默认仍修改传入的 material resource；Inspector UI 是否编辑共享材质或 runtime instance 由编辑器步骤卡决定。

## Boundaries

- 不在本步骤实现 material JSON 保存。
- 不在本步骤实现持久化 per-object material instance asset；runtime instance 只用于编辑器预览和运行时 override。
- 不在本步骤编辑 texture slot；纹理替换需要单独处理 descriptor/binding 生命周期。
- 不让 Editor 直接写 `MaterialGPU::uboBuffer`。
- 不把 shader 成员 offset 写死在 Renderer 或 Inspector 代码中。

## Risks

- 共享 Material resource 会让多个对象一起变化；Inspector 默认应通过 runtime instance 隔离选中对象的参数编辑。
- 如果未来引入 Render Thread，直接写 mapped UBO 需要改成 render command 或双缓冲参数更新。
- Bool 参数在 shader UBO 中的布局可能不是 C++ `bool`，MVP 应优先支持 float/vector，Bool 需要按 reflection size 明确写入。

## Recommended Order

1. 先实现 ResourceManager 的参数 runtime 表和更新函数。
2. 再实现 Renderer Facade 查询/修改接口。
3. 补 ResourceManager 单元测试。
4. 最后接入 Editor Inspector UI。
