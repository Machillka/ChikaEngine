# Step 6.2A - HDR/EXR Skybox Import and Sampling

## Metadata

- Status: Implemented and runtime-validated (2026-07-15)
- Depends on: Step 6.1A and completed Step 6.2
- Unblocks: Step 6.3
- Estimate: 4-6 days

## Goal

让项目配置可以引用六面 HDR/EXR Cubemap，或常见的单张 2:1 equirectangular `.hdr/.exr` 环境图，并将其转换、上传为浮点 Cubemap，最终由现有 Skybox Pass 采样到 HDR Scene Color。

## Result - 2026-07-15

本卡已完成。默认项目直接使用 ambientCG 的 `NightSkyHDRI008_2K_HDR.exr`，通过稳定 `.texture` descriptor 生成 512x512x6 RGBA16F Cubemap。先前只用于验收的程序化 HDR/EXR 样例、独立 EXR 项目配置和样例生成器已删除，运行配置只保留一条真实素材路径。

实现保持原定架构：转换发生在 Asset load/reload，RenderPipeline 仍只看到 `TextureCube + Environment.Skybox`。为避免 EXR 解码和 CPU projection 阻塞首帧，Resolver 通过 Asset JobSystem 异步加载；loading 期间渲染 `fallbackColor`，future 就绪后才由主线程创建、上传 GPU 资源。NightSky Debug 实测 projection 约 938 ms、输出 12 MiB，但这段工作不再阻塞启动线程。

完整数据流：

```text
.texture descriptor
  -> Asset JobSystem: HDR/EXR linear float decode
  -> Asset JobSystem: optional equirectangular-to-cubemap conversion
  -> main thread observes ready future
  -> RGBA16_Float TextureCube + cube view + sampler
  -> ResourceManager cache
  -> RenderGraph Environment.Skybox
  -> existing Skybox Pass
  -> HDRSceneColor
  -> exposure / ACES / display gamma
```

## Decisions

### Configuration entry

- Project 的 `runtime.environment.skybox` 继续引用 `.texture` AssetReference，不直接把裸 `.hdr/.exr` 当作 Skybox。
- `.texture` descriptor 负责说明 projection、输出 face size、浮点格式和 mip 策略；裸文件只负责像素来源。
- 这样可避免“一个 2D equirectangular texture 被 EnvironmentResourceResolver 当作 TextureCube”这种隐式猜测。

### Supported source modes

1. `cubeFaces`：六张尺寸一致的 `.hdr` 或 `.exr`，直接组成 TextureCube。
2. `source + projection=equirectangular`：一张 2:1 lat-long HDR/EXR，在资产加载阶段转换为六面 Cubemap。

首版不支持 cross/strip atlas 自动识别，也不根据文件名猜 face 朝向。

### Conversion ownership

- 首个闭环使用 Asset 层的确定性 CPU conversion helper；转换只在 asset load/reload 时执行，不进入每帧 RenderPipeline。
- CPU 路径便于单元测试 face orientation、seam wrap 和亮度保真，并保持 Asset 层不依赖 Vulkan command list。
- 当前 Debug 性能已经证明同步加载会阻塞首帧，因此运行时改为 Asset JobSystem 异步转换；GPU 创建和上传仍留在主线程/RHI 边界。
- 后续 Cooker 仍可缓存转换结果以减少后台 CPU 与内存成本，但它不再是解决启动卡顿的前置条件。
- 转换必须在线性浮点空间进行，不能先 tone map 或转成 sRGB。

### Projection and orientation

- equirectangular 输入宽高比必须接近 `2:1`；非法比例默认拒绝，除非 descriptor 未来增加显式 crop policy。
- 每个 Cubemap texel 先按固定 `px, nx, py, ny, pz, nz` 约定生成 world direction，再使用 `atan2/asin` 映射到 lat-long UV。
- U 使用 repeat/wrap 处理经线接缝，V 使用 clamp；重采样使用双线性过滤。
- `outputFaceSize` 未配置时默认使用 `sourceWidth / 4`，并受 RHI 最大纹理尺寸限制。
- orientation 必须通过方向色 fixture 验证，不依赖肉眼试错或交换 face 文件名。

### Mip boundary

- 本卡的必要闭环是正确的浮点 mip 0 Skybox 显示。
- 如果 `generateMips` 尚未实现，descriptor 必须设置 `false` 且 `mipLevels=1`；禁止接受互相矛盾的配置。
- 普通显示 mip 与 Step 6.3 的 roughness-dependent specular prefilter 不是同一资源，不能用普通 box-filter mip 冒充 IBL prefilter。

## Descriptor Examples

### Single equirectangular HDR

```json
{
  "usage": "environment",
  "source": "studio.hdr",
  "projection": "equirectangular",
  "outputFaceSize": 1024,
  "format": "rgba16f",
  "srgb": false,
  "generateMips": false,
  "mipLevels": 1
}
```

### Default NightSky equirectangular EXR

```json
{
  "usage": "environment",
  "source": "NightSkyHDRI008_2K_HDR.exr",
  "projection": "equirectangular",
  "outputFaceSize": 512,
  "format": "rgba16f",
  "srgb": false,
  "generateMips": false,
  "mipLevels": 1
}
```

六面输入沿用 Step 6.1A 的 `cubeFaces` contract。

Step 6.1A 的 six-face 路径与本卡的 equirectangular 路径现在都能形成 `RGBA16_Float/RGBA32_Float` TextureCube，并共享相同上传、RenderGraph 和 Skybox sampling 契约。

## Visual Acceptance

- 默认 2K equirectangular 源按 `sourceWidth / 4` 输出 512×512 per-face，避免旧 256×256 诊断样例的清晰度误导。
- 固定相机视角分别朝向 horizon、zenith 和一个高亮光源，截图中细节随相机旋转而移动，且相机平移不改变方向。
- exposure 改变时高亮逐步显现，而不是在 Loader 阶段已经 clamp 成白块。
- RenderDoc 检查绑定 image 是 float Cubemap、6 layers、正确 cube view；不是默认 LDR fallback。
- Vulkan Validation 不出现 copy、layout、view type 或 descriptor 错误。

## Boundaries

- 不在本卡实现 diffuse irradiance、specular prefilter 或 BRDF LUT。
- 不实现动态天空、大气散射或实时环境捕获。
- 不把 equirectangular sampler 直接塞进 Skybox shader；Runtime 统一消费 TextureCube。
- 不为追求“清晰”改用 nearest sampler；清晰度由源分辨率与正确 mip/过滤策略保证。
- 不在每帧重复转换或上传 HDR/EXR。
