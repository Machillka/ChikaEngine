# Step 0.1 - Physics Contract and Runtime Ownership

## Metadata

- Status: Implemented（2026-07-16）
- Priority: Core / Blocker
- Depends on: Current Jolt backend baseline
- Estimate: 2-3 days

## Goal

冻结后端无关的物理基础契约，并把 Jolt 进程级全局状态与每 Scene 的 Physics World 分开管理。后续事件、查询和组件不能继续依赖 raw Jolt BodyID 或隐式全局初始化。

## Implemented result

- `PhysicsRuntime` 通过 move-only `Lease` 管理进程级 Jolt allocator、Factory 和 type registration；首个 Scene 注册，最后一个 Scene 关闭后释放。
- `PhysicsBodyHandle` 与 `PhysicsColliderHandle` 是相互不可混用的 64-bit opaque handle，使用 index + 进程级唯一 generation，零值统一表示 invalid。
- Jolt `BodyID` 只保存在私有 backend registry；Body user data、Raycast 和 CollisionEvent 对外都使用 engine handle。
- `PhysicsScene::Initialize`、backend 初始化与 Body 创建返回带 `PhysicsStatus` 和 diagnostic 的结果；未初始化、失败初始化和重复 Shutdown 均安全。
- `PhysicsBackendCapabilities` 明确报告 Box、Sphere、closest Raycast 已支持，Capsule、constraint、CCD 尚未支持；Capsule 创建返回 `UnsupportedFeature`，不再静默回退。
- Jolt adapter 与 layer helper 已移动到 `src/` 私有边界，Physics public headers 不再包含或前置暴露 `JPH::*`。

## Implementation checklist

- [x] 增加进程级 `PhysicsRuntime` RAII，引用计数或单一 engine ownership；只注册一次 Jolt types，并在所有 world 销毁后释放。
- [x] 定义 `PhysicsBodyHandle`、`PhysicsColliderHandle` 为 index + generation 的 opaque handle，并定义统一 invalid sentinel。
- [x] Jolt BodyID 与 engine handle 的映射只留在 backend/registry，不进入 Framework 公共事件。
- [x] `PhysicsScene::Initialize` 返回可诊断结果；所有接口对未初始化、重复 Shutdown 和 backend failure 安全。
- [x] 清理 `ColliderShapeTypes/RigidbodyShapes` 重复枚举，修正 `oherRigidbodyHandle` 等不再兼容的错误字段。
- [x] 为 backend 声明 capability：supported shapes、queries、constraints、CCD，unsupported feature 返回明确结果。
- [x] 统一单位与坐标约定：米、秒、千克、Y-up、右手系；默认重力明确为 `{0, -9.81, 0}`，项目可覆盖。
- [x] 公共 header 不包含或前置暴露 `JPH::*` 类型。

## Acceptance criteria

- 同一进程可以顺序和同时创建两个 PhysicsScene，销毁任意一个不会使另一个失效。
- stale Body Handle 在 index 被复用后仍被 generation 拒绝。
- Initialize 失败后的 Tick、Query、Shutdown 不崩溃，并返回可识别状态。
- Jolt register/unregister 次数由无窗口测试锁定。
- Physics public headers 不依赖 Jolt include path。

## Remaining risks

- Handle API 的不兼容迁移已覆盖当前 Physics、Framework、Editor 和测试调用点；外部尚未入库的调用方需要改用 `IsValid()`、`Index()`、`Generation()`，不能再把 Handle 当作整数。
- generation 采用进程级单调分配，达到 `uint32_t` 上限后会明确返回 `CapacityExceeded`，不会回绕并重新接受 stale handle。
- 反射生成器在解析 MSVC 标准库时仍打印非致命 Clang diagnostic，但生成、Framework 链接和 Editor 链接均成功；这不是 Step 0.1 引入的运行时失败。

## Boundaries

- 本步骤不实现碰撞广播。
- 不引入第二个真实物理 backend。
- 不把 PhysicsRuntime 改为通用 Service Locator。
