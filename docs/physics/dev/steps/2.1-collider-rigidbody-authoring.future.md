# Step 2.1 - Collider and Rigidbody Authoring

## Metadata

- Status: Planned
- Priority: Core
- Depends on: Step 1.2
- Estimate: 3-4 days

## Goal

把几何碰撞描述从 Rigidbody 中拆出，形成常见引擎的 Collider + Rigidbody 组合，并完成 Reflection、Scene serialization、Inspector 和旧数据迁移。

## Target model

- `Collider`：shape、center、size、material、isTrigger、collision profile、query participation、ColliderID。
- `Rigidbody`：motion type、mass、damping、gravity factor、CCD、sleep、axis lock 和运动 API。
- Collider without Rigidbody：Static Body。
- Collider + Kinematic Rigidbody：由 Transform/Kinematic target 驱动。
- Collider + Dynamic Rigidbody：由物理模拟驱动 Transform。
- MVP 每 GameObject 一个 Collider；Handle/事件契约预留 compound sub-shape ID，后续再开放多个 Collider。

## Planned modules

- new `component/Collider.hpp/.cpp`
- `component/Rigidbody.hpp/.cpp`
- Reflection generated metadata
- Scene serializer/deserializer
- `InspectorPanel` and `SceneHierarchyPanel` Add Component menu
- `PhysicsSubsystem` authoring adapter
- migration tests and scene fixtures

## Implementation checklist

- [ ] 新增独立 Collider component，并将 shape/center/radius/height/halfExtents/trigger/layer 等字段迁入。
- [ ] Rigidbody 只保留动力学字段和运行时 Body Handle，不继续拥有默认 Box。
- [ ] 没有 Collider 的 Rigidbody 显示明确 authoring error，不静默创建默认形状。
- [ ] 没有 Rigidbody 的 Collider 在 Play 时创建 Static Body。
- [ ] 定义旧 Scene 中 Rigidbody collider 字段的兼容读取和一次性迁移策略。
- [ ] Reflection/Inspector 根据 shape 显示 Box、Sphere、Capsule 对应字段，并进行正数/有限值校验。
- [ ] Add/Remove/Enable/Disable/Dirty 只生成 lifecycle command，不直接操作 backend。
- [ ] Collider Gizmo 与真实 world center、rotation、scale 使用同一 shape build 规则。
- [ ] 序列化只保存 authoring 数据，不保存 runtime handles、sleep state 或 contact cache。

## Acceptance criteria

- Static Collider、Dynamic Rigidbody + Collider、Kinematic Rigidbody + Collider 都能正确创建。
- 旧 Scene 可加载并迁移为等效 Collider/Rigidbody 配置，保存后使用新 schema。
- 修改 Collider 字段只重建受影响 Body，并保持 GameObject/Collider identity。
- Inspector Gizmo 与实际碰撞形状在 center、rotation、scale 上一致。
- 缺 Collider、非法尺寸和 unsupported shape 都有可读诊断。

## Verification

- `cmake --build build --target ChikaEditor ChikaColliderAuthoringTests ChikaSceneIntegrationTests`
- `ctest --test-dir build --output-on-failure -R "Chika.ColliderAuthoring|Chika.SceneIntegration"`
- 旧 scene round-trip fixture + 新 schema round-trip fixture。

## Risks

- 这是序列化兼容性变化，必须保留版本化迁移，不能直接让旧场景字段消失。
- 多 Collider 会显著增加 compound shape 和事件路由复杂度，首版明确限制为一个。

## Boundaries

- 不在本步骤开放 MeshCollider cooking。
- 不把 Collider 变成独立 GameObject ownership system。
