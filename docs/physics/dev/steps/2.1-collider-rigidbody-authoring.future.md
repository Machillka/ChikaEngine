# Step 2.1 - Collider and Rigidbody Authoring

## Metadata

- Status: Implemented（2026-07-30）
- Priority: Core
- Depends on: Step 1.2
- Estimate: 3-4 days

## Goal

把几何碰撞描述从 Rigidbody 中拆出，形成常见引擎的 Collider + Rigidbody 组合，并完成 Reflection、Scene serialization、Inspector 和旧数据迁移。

## Target model

- `Collider`：shape、center、size、material、isTrigger、collision profile、query participation、ColliderID。
- `Rigidbody`：motion type、mass、damping、gravity factor、CCD、sleep、axis lock 和运动 API。
- Collider without Rigidbody：Static Body。
- Collider + Kinematic Rigidbody：由 Transform/Kinematic target 驱动。
- Collider + Dynamic Rigidbody：由物理模拟驱动 Transform。
- MVP 每 GameObject 一个 Collider；Handle/事件契约预留 compound sub-shape ID，后续再开放多个 Collider。

## Implemented modules

- `component/Collider.hpp/.cpp`
- `component/Rigidbody.hpp/.cpp`
- Reflection generated metadata
- Scene serializer/deserializer
- `InspectorPanel` and `SceneHierarchyPanel` Add Component menu
- `PhysicsSubsystem` authoring adapter
- migration tests and scene fixtures

## Implementation summary

- `Collider` 现在拥有 shape、center、尺寸、Trigger、layer、inline material 参数、profile 名称和 query participation，并负责 Body create/rebuild/destroy command。
- `Rigidbody` 只提供 motion type、mass、linear/angular damping、gravity factor、CCD、sleep、axis lock 与运动命令；没有 active Collider 时只报告 authoring diagnostic，不再创建默认 Box。
- `PhysicsScene` 在首次 Body 创建时建立独立 Collider handle，atomic rebuild 只替换 Body handle 并保留 Collider identity；Raycast 与 contact event 都返回该 Collider handle。
- Box/Sphere 的 backend shape、query 和 Collider Gizmo 共用 world center/rotation/scale 规则。Box 使用逐轴绝对缩放；Sphere 使用最大绝对轴；Capsule 使用 Y 轴高度和 X/Z 最大半径，但 Jolt Capsule 创建仍按 capability 显式拒绝。
- Scene load 会检测旧 Rigidbody `_colliderCenter/_colliderOffset/_colliderRadius/_colliderHeight/_friction`，在不存在新 Collider 时一次性迁移；再次保存只输出新 schema。
- Inspector 对 Collider/Rigidbody 使用专用控件：按 shape 条件显示字段、有限范围输入、motion/axis lock/CCD/sleep 编辑与可读诊断；Hierarchy 与 Inspector 的 Add Component 均限制一个 Collider/Rigidbody。
- Jolt adapter 已接入 Rigidbody mass、damping、gravity factor、CCD motion quality、sleep 和 axis lock，并使 `queryEnabled=false` 的 Collider 不参与 closest Raycast。

## Implementation checklist

- [x] 新增独立 Collider component，并将 shape/center/radius/height/halfExtents/trigger/layer 等字段迁入。
- [x] Rigidbody 只保留动力学字段和运行时 Body Handle，不继续拥有默认 Box。
- [x] 没有 Collider 的 Rigidbody 显示明确 authoring error，不静默创建默认形状。
- [x] 没有 Rigidbody 的 Collider 在 Play 时创建 Static Body。
- [x] 定义旧 Scene 中 Rigidbody collider 字段的兼容读取和一次性迁移策略。
- [x] Reflection/Inspector 根据 shape 显示 Box、Sphere、Capsule 对应字段，并进行正数/有限值校验。
- [x] Add/Remove/Enable/Disable/Dirty 只生成 lifecycle command，不直接操作 backend。
- [x] Collider Gizmo 与真实 world center、rotation、scale 使用同一 shape build 规则。
- [x] 序列化只保存 authoring 数据，不保存 runtime handles、sleep state 或 contact cache。

## Acceptance criteria

- Static Collider、Dynamic Rigidbody + Collider、Kinematic Rigidbody + Collider 都能正确创建。
- 旧 Scene 可加载并迁移为等效 Collider/Rigidbody 配置，保存后使用新 schema。
- 修改 Collider 字段只重建受影响 Body，并保持 GameObject/Collider identity。
- Inspector Gizmo 与实际碰撞形状在 center、rotation、scale 上一致。
- 缺 Collider、非法尺寸和 unsupported shape 都有可读诊断。

## Risks

- 这是序列化兼容性变化，必须保留版本化迁移，不能直接让旧场景字段消失。
- 多 Collider 会显著增加 compound shape 和事件路由复杂度，首版明确限制为一个。

## Boundaries

- 不在本步骤开放 MeshCollider cooking。
- 不把 Collider 变成独立 GameObject ownership system。
- `collisionProfile` 与 `materialName` 先形成稳定 authoring schema；项目级 profile 响应矩阵由 Step 3.1 实现，stable Physics Material asset/combine mode 由 Step 4.1 实现。
- Capsule authoring、校验和 Gizmo 已存在；真实 Jolt Capsule shape 仍属于 Step 4.1，并通过 capability/diagnostic 明确拒绝而不是错误回退。
- Transform authority、Kinematic target、Dynamic teleport 与渲染插值仍属于 Step 2.2。
