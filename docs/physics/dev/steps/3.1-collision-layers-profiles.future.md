# Step 3.1 - Collision Layers and Profiles

## Metadata

- Status: Planned
- Priority: Core
- Depends on: Step 2.2
- Estimate: 2-3 days

## Goal

用项目级命名 layer、响应矩阵和可复用 profile 统一模拟、Trigger 和 Scene Query 的过滤语义。

## Current problem

- `PhysicsBodyCreateDesc` 含 per-body `collisionMask`，但 Jolt pair filter 实际读取 backend 的 layer mask 数组。
- layer 没有名称、项目配置、Inspector 编辑和序列化来源。
- 过滤只有 collide / not collide，无法清楚表达 Ignore、Overlap、Block。
- Raycast 没有 layer/query filter，因此模拟过滤和查询过滤不一致。

## Target contract

- 32 个 Project Object Layers，ID 0 为 `Default`。
- `CollisionResponse`: `Ignore`、`Overlap`、`Block`。
- 对称 object response matrix 是模拟 pair 的 source of truth。
- `CollisionProfile` 保存 layer、默认响应和 query participation，Collider 可选择 profile 并覆盖受控字段。
- Trigger 对所有非 Ignore pair 使用 Overlap；不施加阻挡响应。
- Query Channel 与 Object Layer 分离的需求先通过 use cases 验证，首版使用 query layer mask，避免提前复制完整 Unreal channel system。

## Planned modules

- new `PhysicsSettings` / `CollisionProfile` data contracts
- Project descriptor/load validation
- Collider reflection and serialization
- Jolt object layer/pair filtering
- query filter integration
- Editor Project Settings and Collider Inspector
- `tests/unit/PhysicsLayerTests.cpp`

## Implementation checklist

- [ ] 定义 32 层名称、响应矩阵、默认 profile 和 schema version。
- [ ] 项目配置缺失时提供稳定默认值；非法 ID、重复名称和非对称矩阵加载失败或规范化并诊断。
- [ ] Body 创建时只保存明确 layer/profile，不保留未消费的 collisionMask 字段。
- [ ] Jolt pair filter 同时尊重 motion broadphase 规则和 response matrix。
- [ ] Overlap pair 使用 sensor/contact setting，不参与 solver，但可进入事件流。
- [ ] profile 修改在安全 fixed-step 边界更新 Body layer/response，并正确刷新 contact pair。
- [ ] Inspector 用名称而非裸数字显示 Layer/Profile。
- [ ] Scene Query 读取同一层定义并支持独立 mask。

## Acceptance criteria

- Ignore 不产生解算和事件；Overlap 只产生 Trigger/Overlap 事件；Block 产生 Collision 与解算。
- Layer/Profile 配置保存、加载和 Editor 选择保持一致。
- 运行时切换 profile 后，旧 contact 正确 Exit，新 response 在下一 fixed step 生效。
- 32 层边界、非法位移和默认配置有测试。
- 模拟过滤与 Raycast/Overlap filter 的命中集合符合文档。

## Verification

- `ctest --test-dir build --output-on-failure -R "Chika.PhysicsLayer|Chika.ProjectDescriptor"`

## Risks

- 现有 mask 是双向 AND；迁移到 response matrix 时必须明确旧行为映射，避免项目加载后碰撞集合变化。
- 运行时变更 layer 可能让 broadphase/contact cache 失效，必须使用 backend 正式 update API。

## Boundaries

- 首版不增加无限自定义 Trace Channel。
- 不把 layer name 硬编码进 JoltLayer.h。
