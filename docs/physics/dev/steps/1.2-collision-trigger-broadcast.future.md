# Step 1.2 - Collision and Trigger Broadcast

## Metadata

- Status: Planned
- Priority: Core
- Depends on: Step 1.1
- Estimate: 2-3 days

## Goal

把 PhysicsScene 的稳定 contact stream 接入 Framework Scene，让 C++ Component、Script 和 Editor/diagnostic observer 都能安全接收碰撞消息。

## Event paths

- Scene observer：通过 `Scene::GetEventBus()` 订阅 canonical `PhysicsPairEvent`，每个 pair/phase 只发布一次，用于工具、调试和跨对象系统。
- Owner-local callback：向 self GameObject 上 active/enabled components 分发：
  - `OnCollisionEnter/Stay/Exit`
  - `OnTriggerEnter/Stay/Exit`
- Script bridge：`ScriptComponent` 将同一 payload 投影到脚本 API，不直接暴露 C++ pointer 或 Jolt type。

## Planned modules

- existing `engine/Runtime/Physics/include/ChikaEngine/PhysicsEvents.hpp` canonical event contract
- new Framework-only owner-local callback view/receiver contract（不得重复定义 `PhysicsPairEvent`）
- `Component` physics callback surface or a dedicated receiver interface
- `ScriptComponent` bridge
- `PhysicsSubsystem`
- `Scene::Tick` fixed-step ordering
- `EventBus` mutation-safety tests
- `tests/integration/PhysicsBroadcastTests.cpp`

## Implementation checklist

- [ ] PhysicsSubsystem 在 Simulate 和 Transform sync 后调用 `PhysicsScene::DrainPairEvents()`，再在主线程 dispatch。
- [ ] 事件 payload 只使用 stable IDs/handles 和值类型；不保存临时 manifold pointer。
- [ ] 对 canonical pair 按稳定 A/B 顺序生成两个 self-oriented callback view，再发布一次 Scene observer event；顺序固定并记录。
- [ ] callback 期间创建/销毁 GameObject 或 Component 走 Scene 既有 deferred mutation，不使接收列表失效。
- [ ] disabled/inactive component 不接收 owner-local callback；Scene observer 是否接收不受其影响。
- [ ] Exit 时 other 已销毁则提供 stable ID 和 `otherAlive=false`，禁止解引用悬空对象。
- [ ] Paused/Edit 不执行模拟，也不重复广播上一 fixed step 的事件。
- [ ] Script callback 参数采用只读 snapshot，脚本异常不能中断其他接收者。
- [ ] Scene StopPlay/Cleanup 清空订阅和待广播事件。

## Acceptance criteria

- C++ Component 和 Script 都能分别收到完整 Collision/Trigger Enter/Stay/Exit。
- 每个参与对象每个 pair/phase 最多收到一次 owner-local callback。
- callback 内销毁 self、other 或移除 receiver 不崩溃，后续接收者规则有测试。
- Scene EventBus observer 每个 canonical pair/phase 只收到一次事件，且没有 Jolt 依赖。
- Paused 后事件数保持不变，继续 Play 后从新的 fixed step 恢复。

## Risks

- EventBus 当前 Publish 会复制 handler 列表，callback mutation 是可行基础，但 owner-local receiver 也必须 snapshot。
- Scene observer 与 owner callback 是两个用途不同的入口，示例文档需避免 gameplay 同时消费两次同一逻辑。

## Boundaries

- 不在本步骤实现 Editor visualizer。
- 不允许 gameplay callback 在 Jolt worker thread 执行。
