# Step 1.2 - Collision and Trigger Broadcast

## Metadata

- Status: Implemented
- Priority: Core
- Depends on: Step 1.1
- Estimate: 2-3 days
- Completed: 2026-07-17

## Goal

把 PhysicsScene 的稳定 contact stream 接入 Framework Scene，让 C++ Component、Script 和 Editor/diagnostic observer 都能安全接收碰撞消息。

## Event paths

- Scene observer：通过 `Scene::GetEventBus()` 订阅 canonical `PhysicsPairEvent`，每个 pair/phase 只发布一次，用于工具、调试和跨对象系统。
- Owner-local callback：向 self GameObject 上 active/enabled components 分发：
  - `OnCollisionEnter/Stay/Exit`
  - `OnTriggerEnter/Stay/Exit`
- Script bridge：`ScriptComponent` 将同一 payload 投影到脚本 API，不直接暴露 C++ pointer 或 Jolt type。

## Implemented result

- `PhysicsPairEvent` 继续作为 Physics 层唯一 canonical contract；新增 Framework-only `PhysicsContactEvent`，只保存 value、stable ID 和 generation-safe handle，不包含 Scene、GameObject、Component 或 Jolt pointer。
- `Component` 增加 Collision/Trigger 的六个虚函数入口；`GameObject` 对当前事件建立 eligible component snapshot，保证 callback 内移除 receiver 不破坏遍历。
- 每个 fixed step 使用 `FixedTick -> Simulate -> SyncTransform -> DispatchEvents` 顺序；`PhysicsSubsystem` drain 一次 canonical stream，并固定按 A owner、B owner、Scene observer 分发。
- B owner view 交换 self/other，并反转 normal 和 relative velocity，使两侧 payload 都保持 self 指向 other。
- 参与 Body/GameObject 已销毁的一侧不再接收 callback；存活侧仍收到 stable ID/handle 与 `otherAlive=false` 的一次 Exit。
- `ScriptComponent` 使用 snake_case 六个回调名，并为每次调用新建 Python 只读 `mappingproxy` snapshot；Python 异常在单个组件边界捕获，不阻断后续组件和 Scene observer。
- 新增 `ChikaPhysicsBroadcastTests`，覆盖 Collision/Trigger 全阶段、顺序、pause/resume、inactive/disabled、销毁/移除 mutation 和脚本异常隔离。

## Public callback surface

```cpp
void OnCollisionEnter(const PhysicsContactEvent& event);
void OnCollisionStay(const PhysicsContactEvent& event);
void OnCollisionExit(const PhysicsContactEvent& event);
void OnTriggerEnter(const PhysicsContactEvent& event);
void OnTriggerStay(const PhysicsContactEvent& event);
void OnTriggerExit(const PhysicsContactEvent& event);
```

脚本使用对应的 `on_collision_enter/stay/exit` 和 `on_trigger_enter/stay/exit`。payload 是只读 mapping，字段包含 phase、kind、双方 GameObject ID、Body/Collider handle、contact 数据及其有效位、termination reason、双方 alive 标记与 fixed step index。

## Dispatch and mutation contract

1. canonical pair 始终按 Step 1.1 的 A/B 稳定顺序处理。
2. A owner 的 eligible component snapshot 全部完成；当前 callback 内的 component disable/remove 从下一事件起生效。
3. A callback 后重新解析参与者。若 B 已 pending destroy 或 Body 已销毁，则跳过 B；否则完成 B snapshot。
4. 最后向 `Scene::EventBus` 发布一次 canonical `PhysicsPairEvent`。EventBus 自身复制 handler 列表，订阅变更从下一次 publish 起生效。
5. `StopPlay` 和 Physics cleanup 通过既有 `ResetSceneState()` 清除 pair cache 与待 drain 事件。EventBus subscription 由订阅者生命周期管理，不因一次 Play session 结束而被隐式删除；Scene Shutdown 才清空整个 EventBus。

## Implementation checklist

- [x] PhysicsSubsystem 在 Simulate 和 Transform sync 后调用 `PhysicsScene::DrainPairEvents()`，再在主线程 dispatch。
- [x] 事件 payload 只使用 stable IDs/handles 和值类型；不保存临时 manifold pointer。
- [x] 对 canonical pair 按稳定 A/B 顺序生成两个 self-oriented callback view，再发布一次 Scene observer event；顺序固定并记录。
- [x] callback 期间创建/销毁 GameObject 或 Component 走 Scene 既有 deferred mutation，不使接收列表失效。
- [x] disabled/inactive component 不接收 owner-local callback；Scene observer 是否接收不受其影响。
- [x] Exit 时 other 已销毁则提供 stable ID 和 `otherAlive=false`，禁止解引用悬空对象。
- [x] Paused/Edit 不执行模拟，也不重复广播上一 fixed step 的事件。
- [x] Script callback 参数采用独立 value snapshot，脚本异常不能中断其他接收者。
- [x] StopPlay/Cleanup 清空 Physics pending event；EventBus subscription 保持 Scene/订阅者既有生命周期语义。

## Acceptance criteria

- C++ Component 和 Script 都能分别收到完整 Collision/Trigger Enter/Stay/Exit。
- 每个参与对象每个 pair/phase 最多收到一次 owner-local callback。
- callback 内销毁 self、other 或移除 receiver 不崩溃，后续接收者规则有测试。
- Scene EventBus observer 每个 canonical pair/phase 只收到一次事件，且没有 Jolt 依赖。
- Paused 后事件数保持不变，继续 Play 后从新的 fixed step 恢复。

## Risks

- EventBus 当前 Publish 会复制 handler 列表；owner-local callback 也采用 snapshot，但 owner A 销毁 owner B 时会在 B dispatch 前重新解析并跳过 B。
- Scene observer 与 owner callback 是两个用途不同的入口，示例文档需避免 gameplay 同时消费两次同一逻辑。

## Boundaries

- 不在本步骤实现 Editor visualizer。
- 不允许 gameplay callback 在 Jolt worker thread 执行。
