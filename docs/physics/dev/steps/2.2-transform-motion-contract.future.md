# Step 2.2 - Transform and Motion Contract

## Metadata

- Status: Implemented（2026-07-30）
- Priority: Core
- Depends on: Step 2.1
- Estimate: 3-4 days

## Goal

明确 Static、Kinematic、Dynamic 的 Transform authority，补齐常见刚体运动方法，并消除每步全量回读所有 Body 的低效同步。

## Authority rules

| Motion type | Authoritative source | Engine behavior |
| --- | --- | --- |
| Static | Transform before simulation | Transform 改变时重建或显式更新静态 Body；运行时频繁移动应改 Kinematic |
| Kinematic | gameplay target | 每 fixed step 使用 `MoveKinematic`，不从 physics 覆盖 gameplay target |
| Dynamic | physics simulation | 模拟后回写 Transform；直接改 Transform 必须走 `Teleport` |

## Implemented API

- `Set/GetLinearVelocity`
- `Set/GetAngularVelocity`
- `AddForce`、`AddTorque`：按 fixed step 持续作用。
- `AddImpulse`、`AddAngularImpulse`：瞬时作用。
- `MoveKinematic(target)`：fixedDeltaTime 在 `PhysicsScene::PreStep` 执行命令时注入。
- `Teleport(position, rotation, resetVelocity, wakePolicy)`
- `WakeUp`、`Sleep`、`IsSleeping`
- linear/angular damping、gravity factor、axis locks。

## Implemented modules

- `Rigidbody`
- `PhysicsSubsystem` PreStep/PostStep
- `PhysicsScene` command and active-body snapshot
- `IPhysicsBackend` motion API
- `PhysicsJoltBackend`
- Transform dirty integration
- render interpolation state
- `tests/integration/PhysicsMotionTests.cpp`

## Implementation summary

- `PhysicsSubsystem::PrepareTransforms()` 在全部 gameplay `FixedTick` 完成后、物理命令提交前统一检查 Transform，避免组件顺序改变 authority：
  - Static pose/scale 改动生成 Collider rebuild。
  - Kinematic pose 改动生成 target，scale 改动生成 rebuild；gameplay Transform 不被 physics 回写。
  - Dynamic pose 只由上一步 physics snapshot 驱动，直接写入会恢复为权威姿态；显式 `Teleport` 通过命令缓冲改变物理状态。
- `PhysicsJoltBackend` 使用 Jolt active rigid-body list，只为 active Dynamic Body 构建位置、旋转、线速度和角速度值快照；sleeping body 不进入常规上传。
- `PhysicsScene` 保存 main-thread snapshot cache。Rigidbody getter、sleep state 和 Framework transform sync 都读取缓存，不在任意线程直接读取 Jolt Body。
- previous/current Dynamic snapshot 与 accumulator alpha 完全独立于 authoring Transform；RenderSubsystem 对 mesh、runtime camera、light 和物理父节点子层级读取 render-facing matrix，插值结果不反馈到 gameplay/physics。
- `FixedStepAccumulator` 与 `Scene::GetPhysicsTimingStatistics()` 暴露 interpolation alpha、last/total dropped time 和 last step count；Profiler 同步记录 fixed steps 与 dropped time，并使用小 epsilon 避免 144 FPS 累积误差漏掉固定步。
- parented physics body 遇到 non-uniform parent world scale 时 authoring validation 明确拒绝，不静默生成变形 shape。

## Implementation checklist

- [x] backend 只返回 active Dynamic Body 的 transform snapshot，不遍历并锁定所有 body。
- [x] Transform dirty 根据 motion type 生成 static update、kinematic target 或明确拒绝 dynamic direct write。
- [x] Dynamic Teleport 定义 wake 和 velocity reset policy。
- [x] Force 与 Impulse 分开，API 名称和单位在注释中明确。
- [x] getter 使用上一步主线程 snapshot，不在任意线程直接访问 Jolt Body。
- [x] 保存 previous/current physics transform，并提供 0..1 interpolation alpha 给 render-facing transform。
- [x] parented physics object 的 world/local transform 转换有单独规则；不允许 parent non-uniform scale 静默破坏 shape。
- [x] fixed step 被 clamp 时记录 dropped physics time/catch-up metric。

## Acceptance criteria

- 30/60/144 FPS 输入下，相同 fixed step 的 Dynamic 轨迹在容差内一致。
- Kinematic Body 按 target 移动并正确推动 Dynamic Body。
- Dynamic direct Transform edit 不产生一帧瞬移后又被物理覆盖的抖动。
- Interpolation 只影响显示，不反馈到物理 world。
- Sleeping Dynamic Body 不进入常规 transform upload，Wake 后恢复。
- Force、Impulse、Torque 和 axis lock 有数值测试。

## Risks

- 插值缓存属于 `PhysicsSubsystem` transient state，不参与序列化；Renderer 只消费矩阵值。
- Kinematic 公共 API 不让调用方传任意 dt，固定步 dt 由 Scene orchestration 在命令执行时注入，避免 target 速度与物理步长不一致。

## Boundaries

- 不在本步骤实现网络 prediction/rollback。
- 不把固定步长 accumulator 移入 backend；Scene 继续拥有 gameplay fixed-step orchestration。
