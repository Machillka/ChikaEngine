# Step 4.1 - Shapes, Materials, CCD and Sleep

## Metadata

- Status: Planned
- Priority: Extension
- Depends on: Step 3.2
- Estimate: 4-5 days

## Goal

补齐常见碰撞形状和刚体质量属性，使 Collider authoring、Gizmo、查询和 Jolt shape 的行为一致，并为高速物体提供 CCD。

## Existing baseline from Step 2.1

- Box/Sphere 已共用 Collider world center/scale build rule，且 center offset 已进入 Jolt decorated shape。
- Rigidbody 已有 per-body Discrete/Continuous、allow sleep、mass、damping、gravity factor 与 axis lock authoring，并映射到 Jolt creation settings。
- Collider 已有 inline friction/restitution 与 material name schema；本步骤仍需 stable Physics Material asset、density/inertia policy 和 combine mode。
- Capsule authoring、校验和 Gizmo 已就绪，但 backend capability 仍为 unsupported；本步骤负责真实 shape 与端到端模拟/query 验收。

## Shape scope

### Required

- Box
- Sphere
- Capsule
- Convex Hull（Dynamic/Kinematic/Static）
- Triangle Mesh（Static only）

### Deferred

- HeightField、compound authoring、mutable compound、runtime arbitrary mesh cooking。

## Physics material scope

- friction
- restitution
- density / mass contribution
- friction combine mode
- restitution combine mode
- stable material asset/reference identity

## Planned modules

- Collider shape descriptors and validation
- Physics Material asset/import/serialization
- Rigidbody mass and inertia calculation
- Jolt shape factory/cache
- mesh/convex cooking boundary
- CCD, sleep and motion quality settings
- Collider Gizmo/debug drawing
- `tests/integration/PhysicsShapeTests.cpp`

## Implementation checklist

- [ ] Capsule enum 创建真实 Capsule，不再落入 Sphere default case。
- [x] Box/Sphere 的 center、rotation、world scale 在 shape build、Gizmo、query 中使用同一转换规则（Step 2.1）。
- [ ] Box/Sphere/Capsule 尺寸必须 finite 且大于最小容差；非法输入不创建退化 shape。
- [ ] non-uniform scale 规则按 shape 明确；Sphere/Capsule 不能静默变成错误几何。
- [ ] Convex/Mesh cooking 产物进入 Asset/Resource 流程，不在每次 Play 启动重复计算。
- [ ] Dynamic Triangle Mesh 被拒绝并提供 Convex 建议。
- [ ] Physics Material 使用 stable asset reference，缺失时回退到项目默认材质。
- [ ] mass mode 支持 explicit mass 和 density-derived mass；inertia 由后端 shape 计算。
- [x] Rigidbody 暴露 Continuous/Discrete motion quality，并映射到 Jolt（Step 2.1）；性能统计与 tunneling fixture 留在本步骤。
- [ ] sleep threshold、start awake 和 wake-on-command 语义有测试；基础 allow sleep 字段已由 Step 2.1 接入。
- [ ] shape cache 使用明确 ownership，不因 Collider 重建泄漏。

## Acceptance criteria

- 五种 required shape 的模拟、query、Gizmo 尺寸一致。
- Capsule、center offset、rotation 和支持的 scale 组合有端到端测试。
- 高速小球在 Discrete case 可复现 tunneling，在 CCD case 被薄墙阻挡。
- material combine 结果与规则一致，Trigger 不施加 friction/restitution。
- Convex/Mesh cooked data 可复用，第二次场景加载不重复 cooking。
- sleep body 数和 wake 行为可观测且无无意义 transform sync。

## Verification

- `cmake --build build --target ChikaPhysicsShapeTests ChikaAssetPipelineTests`
- `ctest --test-dir build --output-on-failure -R "Chika.PhysicsShape|Chika.AssetPipeline"`
- CCD thin-wall fixture、shape scale matrix 和 material combine cases。

## Risks

- Mesh cooking 会引入 Asset pipeline 变化，应优先复用现有 GUID/meta/cooked layout，不在 Physics 自建文件系统。
- CCD 对性能有显著成本，默认只允许按 Rigidbody 开启并记录统计。

## Boundaries

- 不支持 Dynamic Triangle Mesh。
- 不实现 soft body、cloth 或 destructible mesh。
