# Step 4.2 - Physics Constraints

## Metadata

- Status: Planned
- Priority: Extension
- Depends on: Step 4.1
- Estimate: 3-4 days

## Goal

以后端无关方式提供常用刚体约束，并建立 Constraint 生命周期、序列化和 Inspector 边界。

## Initial constraint set

- Fixed Constraint
- Distance Constraint
- Hinge Constraint

后续根据真实 gameplay 需求再增加 Slider、Cone、SixDOF、Gear 和 Pulley。

## Planned modules

- new `PhysicsConstraintHandle` and descriptors
- `IPhysicsBackend` constraint capabilities
- `PhysicsScene` constraint registry/command buffer
- Framework constraint components
- Jolt constraint adapters
- Scene serialization and Inspector
- `tests/integration/PhysicsConstraintTests.cpp`

## Implementation checklist

- [ ] Constraint 使用 engine handle + generation，不暴露 Jolt Constraint pointer。
- [ ] 支持 world anchor、local anchor、axis、limit、spring/damping 的最小公共契约。
- [ ] Hinge 支持 angle limit；motor 只有在基础约束稳定后作为同卡片后半验收。
- [ ] Body create 后创建 Constraint，Body destroy 前销毁相关 Constraint，顺序由 command buffer 保证。
- [ ] 对端 GameObject 不存在、非 Rigidbody 或被销毁时安全禁用并诊断。
- [ ] `collideConnected` 显式控制已连接 Body 是否互相碰撞。
- [ ] Scene serialization 保存对象稳定 ID 引用，不保存 runtime Body/Constraint Handle。
- [ ] Editor Gizmo 显示 anchor、axis 和 limit 范围。
- [ ] 可选 break force/torque 在实现前先确认 Jolt 能力；unsupported 时不伪造。

## Acceptance criteria

- Fixed、Distance、Hinge 在创建、禁用、重启 Play 和场景 round-trip 后行为一致。
- 删除任一连接 Body 不产生悬空 Constraint。
- Hinge limit、Distance min/max 和 collideConnected 有测试。
- 同一场景多 Constraint 的创建/销毁顺序稳定。
- backend capability 不支持时返回明确错误而不是静默跳过。

## Verification

- `cmake --build build --target ChikaPhysicsConstraintTests ChikaSceneIntegrationTests`
- `ctest --test-dir build --output-on-failure -R "Chika.PhysicsConstraint|Chika.SceneIntegration"`
- constraint lifecycle、serialization reference 和 limit cases。

## Risks

- Constraint 对两个 Body 生命周期均有依赖，不能由任一 Component 独占 raw backend pointer。
- Parent hierarchy 和 physics constraint 同时控制 Transform 容易形成双重约束，需在 Editor 提示。

## Boundaries

- 首版不一次实现全部 Jolt constraint 类型。
- 不实现 ragdoll authoring；ragdoll 应在约束稳定后独立规划。
