# Step 1.1 - Contact State Stream

## Metadata

- Status: Implemented
- Completed: 2026-07-16
- Priority: Core
- Depends on: Step 0.2
- Estimate: 3-4 days

## Goal

把 Jolt 多线程 contact callbacks 转换为后端无关、主线程可消费、可去重的 Collision/Trigger Enter、Stay、Exit 流。

## Implemented result

- `PhysicsEvents.hpp` 定义 backend-neutral `RawContactPacket`、`PhysicsPairEvent`、canonical `PhysicsPairKey` 与每项 contact 数据的有效位。
- Jolt listener 实现 Added、Persisted、Removed；Removed 只读取 callback 前缓存的 POD identity，不访问已经无效或被锁定的 Body。
- `PhysicsJoltBackend::DrainRawContactPackets()` 只在 `PhysicsSystem::Update` 返回后补充 Body exists/active、`WereBodiesInContact` 和 removal 分类。
- `PhysicsScene` 按排序后的 Body/Collider Handle 维护 pair cache，按 sub-shape feature 聚合，并为每 pair/fixed-step 生成最多一个同 phase canonical event。
- sleep/deactivation removal 保留 pair state，不生成伪 Exit；真实分离、Body destroy 分别生成带 `Separated`、`BodyDestroyed` 原因的 Exit。
- Body destroy/rebuild 在调用 backend destroy 前暂存 Exit；若 backend destroy 失败则撤销，成功后清理 pair cache。事件直到下一次 backend Update 返回后才可 drain。
- Scene Reset/Shutdown 清空 raw queue、listener identity cache、pair cache 与 pending events，不跨 Play session 泄漏。

## Planned contract

```text
RawContactPacket
  phase: Added | Persisted | Removed
  bodyA/bodyB: engine handles
  colliderA/colliderB
  point/normal/penetration when available
  isSensorPair
  fixedStepIndex

PhysicsPairEvent
  phase: Enter | Stay | Exit
  kind: Collision | Trigger
  canonical A/B body, collider and GameObject IDs
  contact manifold summary
  relativeVelocity / impulse when available
  hasContactData
  terminationReason when exiting
```

Jolt Added/Persisted 位于 solver 前，因此当前 `relativeVelocity` 可用，`impulse` 明确保持 `hasImpulse=false`；不以数值 `0` 冒充真实冲量。Collider Handle 在 Step 2.1 独立 Collider 落地前保持 invalid 占位。

## Implementation checklist

- [x] Jolt callback 只复制 POD packet，不查 Scene、不发布 EventBus、不调用 Body mutation API。
- [x] 实现 Added、Persisted、Removed，并按 Jolt 规则为 Removed 使用预先缓存的 pair identity。
- [x] 使用排序后的 body/collider pair key；同一 fixed step 聚合 sub-shape contacts。
- [x] Added/Persisted/Removed 与 activation/removal 信息共同驱动 pair state；sleep/deactivation 不直接产生伪 gameplay Exit。
- [x] 根据 sensor 生成 Trigger 或 Collision 类型，不让 Trigger 进入冲量/接触解算语义。
- [x] PhysicsScene 只生成一次 canonical pair event；Framework 在 Step 1.2 投影 A/B self-oriented view。
- [x] contact point、normal、penetration、relative velocity 和 impulse 使用显式有效位。
- [x] Body destroy 前通知 pair cache，向存活对端生成一次 Exit 后清理。
- [x] drain 后事件按 fixed-step、phase、pair key 稳定排序，确保测试和 replay 可预测。

## Acceptance criteria

- 两个 Box 接触三步后分离，精确产生一次 canonical Enter、若干 Stay、一次 Exit。
- Trigger 穿越只产生 Trigger 序列，不产生物理解算 Collision 序列。
- canonical pair 顺序和 normal 约定稳定，Step 1.2 的 A/B view 可无歧义生成。
- 同一 pair 多 contact point 不产生重复 Enter。
- Body 在接触中销毁不会访问无效 Jolt Body，也不会遗留 pair cache。
- 事件只在 `PhysicsSystem::Update` 返回后被 PhysicsScene 消费。

## Remaining constraints

- Jolt sleep removal 使用 post-step active 状态与 `WereBodiesInContact` 区分；运行时 filter/profile 变更的精确 `FilterChanged` 原因留给 Step 3.1 的安全 fixed-step layer update。
- 真实 solver impulse 尚无 post-solve provider，继续以 `hasImpulse=false` 表达 unavailable。
- Collider Handle 在 Step 2.1 前为 invalid，占位不会影响以 Body Handle 为主的 pair 稳定性。

## Boundaries

- 本步骤只产出 PhysicsScene events，不调用 gameplay component。
- 不实现复杂 contact modification 或 one-way platform。
