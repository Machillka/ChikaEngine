# Step 1.1 - Contact State Stream

## Metadata

- Status: Planned
- Priority: Core
- Depends on: Step 0.2
- Estimate: 3-4 days

## Goal

把 Jolt 多线程 contact callbacks 转换为后端无关、主线程可消费、可去重的 Collision/Trigger Enter、Stay、Exit 流。

## Current problem

- 只有 `OnContactAdded` 生成两份 raw 事件；Persisted 和 Removed 为空。
- Added 时 solver 尚未运行，当前 `impulse` 固定为 0，却没有表达“不可用”。
- Removed callback 无法安全访问 Body，当前也没有缓存 pair owner 信息。
- 多 sub-shape contact 可能让同一 Body pair 在一帧重复广播。
- 当前事件只保存 Body Handle，Body 被销毁或复用后无法可靠解析。

## Planned contract

```text
RawContactPacket
  phase: Added | Persisted | Removed
  bodyA/bodyB: engine handles
  colliderA/colliderB
  point/normal/penetration when available
  isSensorPair
  fixedStepIndex

PhysicsPairEvent
  phase: Enter | Stay | Exit
  kind: Collision | Trigger
  canonical A/B body, collider and GameObject IDs
  contact manifold summary
  relativeVelocity / impulse when available
  hasContactData
  terminationReason when exiting
```

## Planned modules

- `PhysicsDescs.h` or new `PhysicsEvents.hpp`
- `IPhysicsBackend`
- `PhysicsJoltBackend::JoltBackendContactListener`
- `PhysicsScene` contact pair cache and event drain
- `tests/integration/PhysicsContactTests.cpp`

## Implementation checklist

- [ ] Jolt callback 只复制 POD packet，不查 Scene、不发布 EventBus、不调用 Body mutation API。
- [ ] 实现 Added、Persisted、Removed，并按 Jolt 规则为 Removed 使用预先缓存的 pair identity。
- [ ] 使用排序后的 body/collider pair key；同一 fixed step 聚合 sub-shape contacts。
- [ ] Added/Persisted/Removed 与 activation/removal 信息共同驱动 pair state；sleep/deactivation 不直接产生伪 gameplay Exit。
- [ ] 根据 sensor/response 生成 Trigger 或 Collision 类型，不让 Trigger 进入冲量/接触解算语义。
- [ ] PhysicsScene 只生成一次 canonical pair event；Framework 在 Step 1.2 投影 A/B self-oriented view。
- [ ] contact point、normal、penetration、relative velocity 和 impulse 使用显式有效位。
- [ ] Body destroy 前通知 pair cache，向存活对端生成一次 Exit 后清理。
- [ ] drain 后事件按 phase、pair key 稳定排序，确保测试和 replay 可预测。

## Acceptance criteria

- 两个 Box 接触三步后分离，精确产生一次 canonical Enter、若干 Stay、一次 Exit。
- Trigger 穿越只产生 Trigger 序列，不产生物理解算 Collision 序列。
- canonical pair 顺序和 normal 约定稳定，Step 1.2 的 A/B view 可无歧义生成。
- 同一 pair 多 contact point 不产生重复 Enter。
- Body 在接触中销毁不会访问无效 Jolt Body，也不会遗留 pair cache。
- 事件只在 `PhysicsSystem::Update` 返回后被 PhysicsScene 消费。

## Verification

- `cmake --build build --target ChikaPhysicsContactTests`
- `ctest --test-dir build --output-on-failure -R "Chika.PhysicsContact"`
- ThreadSanitizer 可用时对 raw queue 和 pair cache 做额外验证。

## Risks

- Jolt sleep 会触发 contact removal，不能直接映射为 gameplay Exit；需要 activation 信息、post-step contact check 或等效状态策略区分真实分离。
- 真实 solver impulse 不应在 pre-solve Added callback 伪造；需要 post-step 数据或保留 unavailable。

## Boundaries

- 本步骤只产出 PhysicsScene events，不调用 gameplay component。
- 不实现复杂 contact modification 或 one-way platform。
