# Step 6.1 - Physics Debug, Profiling and Regression Gates

## Metadata

- Status: Planned
- Priority: Required gate
- Depends on: Steps 0.1-5.1 incrementally; final gate after Step 5.1
- Estimate: 3-4 days

## Goal

建立可观察、可回归、可测量的物理质量门禁。每个前置卡片必须增量添加测试，本步骤负责统一工具、场景和最终 acceptance matrix。

## Debug tooling

- Collider/constraint/character Gizmo
- contact point、normal、pair phase 和 Trigger 标记
- body AABB、motion type、sleep/active、layer/profile
- last-N queries：shape、filter、hit/miss 和耗时
- selectable GameObject 的 physics handle/owner/backend mapping
- fixed-step accumulator、steps/frame、dropped time

## Profiling counters

- simulate、PreStep commands、transform sync、contact normalize、event dispatch、queries
- active/sleep/static/kinematic/dynamic body counts
- contacts/pairs/events by phase
- commands accepted/rejected/stale
- query count/hits and temporary allocation count
- shape cache/cooked resource hit rate

## Regression suites

- Contract/runtime ownership
- Body lifecycle stress
- Collision/Trigger event sequence
- Callback mutation safety
- Collider serialization migration
- Transform/motion multi-frame-rate oracle
- Layer/profile response matrix
- Raycast/Sweep/Overlap queries
- Shape/material/CCD/sleep
- Constraints
- Character obstacle course

## Planned modules

- Physics debug snapshot API
- Debug/Gizmo renderer integration
- Profiler scopes/counters
- headless physics test fixtures
- benchmark scene and JSON report integration
- `tests/` CMake registration and labels
- physics docs/result records

## Implementation checklist

- [ ] debug snapshot 是只读值数据，不允许 Editor 直接访问 Jolt world。
- [ ] debug draw 可按类别、layer 和 selected object 过滤，默认关闭重成本视图。
- [ ] Profiler 事件名称稳定并记录单位。
- [ ] 所有测试可 headless 运行，随机 case 使用固定 seed 并打印 seed。
- [ ] event sequence tests 使用 fixed step index，不依赖 wall clock。
- [ ] 增加 1k/10k body 基准分层；先记录 baseline，不凭主观设定不现实阈值。
- [ ] 对 body/contact/query 临时分配建立可观测计数。
- [ ] Debug build 验证 stale handles、invalid shapes 和 wrong-thread calls。
- [ ] 每张已实现卡片更新状态、实际文件、验证和剩余限制。

## Final acceptance criteria

- 核心 M0-M3 测试全部自动通过，M4-M5 已实现能力各有对应测试。
- Editor 中能定位“为什么没有碰撞/为什么没有事件/为什么查询未命中”。
- 1k active Dynamic Body benchmark 无持续增长的 Body、contact、command 或 shape allocations。
- Scene Play/Stop 100 次后 physics counts 回到 baseline。
- Validation/Debug 日志没有 Jolt lifecycle、stale handle 或 wrong-thread error。
- 文档中的 implemented/planned 状态与代码和测试一致。

## Verification

- `cmake --build build`
- `ctest --test-dir build --output-on-failure -L physics`
- `ctest --test-dir build --output-on-failure -R "Chika.Physics|Chika.CharacterController"`
- Physics benchmark command 由实现时接入现有 ChikaBenchmark CLI，并将结果写入 build 目录。
- Editor manual smoke：debug categories、selected object、contact、query 和 constraint visualization。

## Risks

- Debug draw 本身可能改变性能结果，benchmark 必须分别记录 disabled/enabled。
- 过早设置绝对性能阈值会掩盖硬件差异；先保存 workload、统计字段和 baseline，再确定 regression tolerance。

## Boundaries

- 不把第三方 Jolt debug renderer API直接暴露给 Editor。
- 不因测试困难而降低事件、销毁或线程语义。
