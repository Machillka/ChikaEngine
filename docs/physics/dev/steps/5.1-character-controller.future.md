# Step 5.1 - Character Controller

## Metadata

- Status: Planned
- Priority: Extension
- Depends on: Step 4.1, Step 1.2, Step 3.2
- Estimate: 4-5 days

## Goal

实现适合角色移动的独立 CharacterController，避免用 Dynamic Rigidbody + 直接 SetVelocity 模拟所有角色行为。

## Target behavior

- Capsule-based controller
- desired velocity / move input
- grounded state、ground normal、ground velocity
- slope limit
- step up / step down
- skin/contact offset
- gravity and jump helper
- moving platform following
- collision/trigger event bridge
- teleport and resize/crouch validation

## Architecture decision

CharacterController 是 gameplay-facing controller，不继承 Rigidbody，也不复用 Dynamic Body authority。Jolt `CharacterVirtual` 或等效 backend capability 位于 Physics backend，Framework 只消费后端无关 snapshot 和 contact event。

## Planned modules

- new Framework `CharacterController` component
- new Physics character descriptors/handles/snapshots
- `IPhysicsBackend` character capability
- Jolt CharacterVirtual adapter/listener
- PhysicsSubsystem fixed-step integration
- Inspector/Gizmo and Script API
- `tests/integration/CharacterControllerTests.cpp`

## Implementation checklist

- [ ] 输入只保存 desired motion，在 fixed step 统一求解，不从 variable Update 直接修改 backend。
- [ ] grounded 判定包含 slope、contact normal 和最大离地距离，不只比较 Y velocity。
- [ ] step/slope 参数采用米和角度，并做 finite/range validation。
- [ ] controller query 使用 Step 3.2 filter，与 layer/profile/trigger 规则一致。
- [ ] moving platform 使用 ground body velocity/transform delta，不把 controller 设为其层级 child。
- [ ] controller contacts 转换为标准 PhysicsPairEvent，再复用 owner-local callback 投影，避免第二套 gameplay callback。
- [ ] resize/crouch 前执行 overlap test，空间不足时保持原尺寸。
- [ ] Teleport 清理 ground/contact cache，并定义下一 fixed step 的 Enter 行为。
- [ ] unsupported backend 返回 capability error。

## Acceptance criteria

- 平地、斜坡、台阶、墙角、移动平台和低顶 crouch 场景行为稳定。
- 30/60/144 FPS variable update 下 fixed-step 轨迹在容差内一致。
- Controller 能触发 Trigger，且与 Dynamic Body 接触事件不重复。
- 超过 slope limit 不被判定 grounded；step 高于限制无法攀爬。
- resize 被阻挡时不穿透环境。

## Verification

- `cmake --build build --target ChikaCharacterControllerTests`
- `ctest --test-dir build --output-on-failure -R "Chika.CharacterController"`
- headless obstacle course fixture + moving platform + trigger cases。

## Risks

- 角色手感高度依赖参数，自动测试锁定物理正确性，不替代 gameplay tuning。
- CharacterVirtual contacts 与 rigid body contacts 来源不同，必须在 PhysicsScene 层归一化和去重。

## Boundaries

- 不实现完整 movement ability system、攀爬、游泳或网络预测。
- 不把 CharacterController 当作通用 Rigidbody 替代品。
